# Research: лёгкие альтернативы cortex-плагину (Obsidian / Notion / аналоги)

Дата: 2026-09-07 · Дополняет: effgenij-cortex-design-20260907-201842.md (APPROVED)
Вопрос: можно ли получить визуализацию данных перед глазами без разработки плагина — готовыми инструментами?

## Варианты

### A. Obsidian как база + Hermes как мозг (recommended, effort S — дни)
- Obsidian установлен на Mac; у Hermes готовый бандл-скилл `obsidian-vault` (filesystem-first: чтение/поиск/создание/правка markdown, wikilinks).
- **Obsidian Bases** (core с 2025): Notion-стиль представления поверх frontmatter — таблицы, карточки, фильтры, формулы. Сообщество массово мигрировало с Dataview на Bases (быстрее, нативно, больше не beta-зависимость).
- Канбан — community Kanban plugin; календарь — Full Calendar / Daily notes; стрики — Bases формулы или Dataview/Datacore.
- Схема работы: vault = единое хранилище; агент пишет заметки с frontmatter напрямую в файлы; cron-рутины обновляют daily note / журналы; Bases-дашборд поверх папок даёт «открыть вкладку и увидеть сегодняшее»; чат Hermes остаётся штатным рядом.
- Учебный конвейер (этап 2 из дока) ложится без переделки: конспекты, SRS-карточки, тесты — заметки в папках + агент в чате; прогресс — frontmatter-поля, видимые в Bases.
- Синхронизация 3 машин: git (приватный репо) / Obsidian Sync / iCloud; агент ходит по файлам на той машине, где живёт профиль.
- Слабые места: строгая статистика (агрегаты КБЖУ, фин-числа, спарклайны) ограничена формулами Bases; связи между записями слабее SQLite; вьюхи = набор Bases+плагинов, не свои; нет двусторонних виджетов в чате.

### B. Notion + MCP/API (effort S, но операционные минусы)
- Ноль своего кода; вьюхи готовые; Notion Custom Agents (2026).
- Минусы: оплата из РФ проблемна; данные в облаке; агент через REST — медленно и дорого по токенам; миграция данных в будущий standalone болезненная.

### C. Anytype (effort S-M)
- Local-first, бесплатный, официальный MCP-сервер (anyproto/anytype-mcp) — агент подключается стандартно.
- Минусы: экосистема молодая, вьюхи беднее (table/kanban/gallery), agent-workflow сообщество только нащупывает.

### D. AFFiNE / AppFlowy self-hosted на VPS (effort M-L, ops навсегда)
- Ближайшие открытые клоны Notion: databases + kanban + calendar (AFFiNE + whiteboard; AppFlowy + локальный Ollama).
- Минусы: Docker-сервер на VPS, ограниченный/сырой API для агента, ops-нагрузка; по сути обмен «код плагина» на «админство сервера».

### E. Свой плагин по approved-доку (без изменений)
- Уникальные ценности, которых нет ни в A–D: двусторонние ::preview-виджеты в чате, строгие типизированные статистики (SQLite), свой хоум-дашборд, точный трёхколоночный UX, чистый перенос в standalone.

## Синтез
- A закрывает ~80% боли («не вижу данные перед глазами») за ~5% усилий от плагина.
- A и E не конфликтуют: vault = этап 1 (недели → дни), плагин = этап 2 по явному триггеру («Bases упёрлись: нужна строгая статистика/свои вьюхи/виджеты в чате»).
- B/D отклонены (оплата/облако/ops), C — запасной, если захочется local-first СУБД-подхода без своего кода.

## Решение (D10, 2026-09-07)
**Остаёмся на собственном плагине как этапе 1 (approved-док без изменений).** Исследование сохранили для истории: Obsidian+Bases — запасной путь, если разработка встанет или понадобится быстрый результат до готовности плагина.
